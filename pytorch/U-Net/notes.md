## 一、数据的几个概念

**掩膜（mask）是什么**
一张只有两种取值的图：255 表示前景（这里是细胞核），0 表示背景。分割任务的标签就是它。

**前景 / 背景 / 前景占比**
前景 = 我们关心的目标（细胞核），背景 = 其余部分。
前景占比 = 掩膜里为 1 的像素数 ÷ 总像素数，用 `mask_bin.mean()` 一行就能算出来。

它衡量的是**类别不平衡**有多严重。前景占比越低，模型「全猜背景」就越占便宜——这就是分割任务不能看准确率、要看 Dice 的根本原因。

**为什么是 `mask > 127`**
把 0/255 的存储格式转成 0/1 的数学格式。损失函数要求标签是 0 到 1 的浮点数，直接喂 255 会让损失算出天文数字、梯度异常，表现为「损失怎么都不降」。

127 是 0 和 255 的中点。对本数据集来说写 `> 0` 结果一样，但真实掩膜常有抗锯齿、压缩产生的中间值，用 127 能把这类噪声挡掉。这个操作叫**二值化**，127 叫**阈值**。

**为什么要把实例掩膜合并**
DSB 原始标注是**实例级**的：每个细胞核一个文件（一张图里几十个）。但训练的是**二值分割**，模型输出 1 个通道，标签也只能是 1 张图，所以要合并。

因果链：任务定义成二值分割 → 模型输出 1 个通道 → 标签必须 1 个通道 → 合并实例掩膜。

合并的代价：丢失「哪个像素属于哪个核」的信息，挨着的细胞核会连成一片。可以用 `cv2.connectedComponents` 对比「连通区域数」和「实际核数」，量化这个损失。

三种任务粒度的区别：

| 任务粒度 | 模型输出 | 标签形态 |
| --- | --- | --- |
| 二值分割 | 1 个通道 | 一张 0/1 图 |
| 多类分割 | C 个通道（C = 类别数） | 一张取值为 0/1/2… 的图 |
| 实例分割 | 每个实例一张掩膜 | 每个目标一个文件 |

## 二、卷积是怎么工作的

**输入通道是什么**
一张 RGB 图 = 一张图，被拆成三个 256×256 的数值矩阵。它们不是三张图，是同一条数据的三个**通道**。

通道必须作为独立维度保留，不能横向拼成 256×768——否则卷积核会跨到拼接边界，把 R 的边缘和 G 的边缘当成相邻像素，物理上没有意义。

**一个卷积核在做什么**
一个核不是 3×3，而是一个 `3×3×3` 的**小立方体**（对上输入的 3 个通道，每层一个 3×3 权重表），共 27 个权重 + 1 个偏置。

在输出位置 (x, y) 上：

```
输出[x, y] = 偏置 + Σ Σ Σ 输入[c, x+i, y+j] × 权重[c, i, j]
                    c i j
            └──────── 一共 27 项 ────────┘
```

27 个数加权求和 → **1 个数**。然后核挪一格重复，一共做 256×256 次。

**通道的融合发生在每一个位置**，不是在最后统一做。
用 `1×1` 卷积最容易验证：R 全 5、G 全 7、B 全 9，权重设成 1、2、3，输出全是 `1×5 + 2×7 + 3×9 = 46`。

**滑动次数 vs 卷积核个数**（最容易混的一点）

| | 由什么决定 | 决定了什么 |
| --- | --- | --- |
| 空间尺寸 256×256 | 卷积核**滑动多少次** | 每张特征图有多大 |
| 特征图张数 64 | 你用了**几个**卷积核 | 提取多少种特征 |

**一个核滑完一整圈 = 产出 1 张特征图。** 64 个核各滑一圈 = 64 张。滑动过程中累积出的 65536 个数是排在一张图里的坐标，不是 65536 张新图。

**特征图是什么**
不是原图的复制品，而是「这张图里哪里有某种模式」的响应图。不同的核学不同的模式（水平亮边、45 度暗边……），浅层学简单模式，深层学高级语义。

**权重共享与参数量**
同一个核在所有位置用同一组权重，所以参数极少：

```
64 个核 × (3×3×3 + 1) = 64 × 28 = 1792 个参数
```

只有 1792 个参数却产出 400 多万个数——这就是卷积比全连接高效的原因。

权重张量的形状读法：`[输出通道数, 输入通道数, 核高, 核宽]`

```python
net.inc.block[0].weight.shape    # torch.Size([64, 3, 3, 3])
```

**规律**：每个核的「厚度」= 输入通道数；输出通道数 = 核的个数。输入通道数只影响核有多厚，不影响有几张输出图。

> 补充：把 3 个通道想成「分别卷一遍再相加」在**算术上是等价的**（加法可交换），是个合法的直觉。区别只在实现层面：实际不会产生 3 张中间图，一个核就是一个立方体，一起算，只有一个偏置。

## 三、下采样与感受野

**下采样 = 池化（在这个网络里）**
`nn.MaxPool2d(2)` 就是下采样。下采样是通用概念，池化只是实现手段之一（另一种是 stride=2 的卷积，带可学习参数）。

**「缩小」缩的是什么**
缩的是数值矩阵的尺寸。2×2 最大池化 = 每个 2×2 方块里取最大值合成 1 个值：

```
输入 4×4                     输出 2×2
[[1, 3, | 2, 0],             [[9, 2],
 [5, 9, | 1, 2],      →       [3, 8]]
 ---------------
 [0, 1, | 4, 6],
 [2, 3, | 8, 7]]
```

16 个数变成 4 个数，宽高各减半，元素总数变成四分之一。

两点补充：这是**有损**的（每个方块只留最大值）；丢掉的恰恰是**位置精度**——所以解码器最后要靠跳连把位置信息补回来。

**为什么同样大小的核能看到更远**
下采样后，图上相邻两个「像素」在原图上的间距变大了。一个 3×3 卷积覆盖的原图范围：

| 所在层 | 特征图尺寸 | 一个 3×3 卷积覆盖原图 |
| --- | --- | --- |
| 不池化 | 256×256 | 3×3 = 9 |
| 池化 1 次 | 128×128 | 6×6 = 36 |
| 池化 2 次 | 64×64 | 12×12 = 144 |
| 池化 3 次 | 32×32 | 24×24 = 576 |
| 池化 4 次 | 16×16 | 48×48 = 2304 |

核一直是 3×3、从没变大，是**脚下的坐标刻度被放大了**。这张表算的是单层直接覆盖范围，实际感受野会沿路径累积，比这大得多。

**空间与通道同时变化**

| 层 | 空间尺寸 | 通道数 | 元素总数 |
| --- | --- | --- | --- |
| 输入 | 256×256 | 3 | 196,608 |
| 编码器 1 | 256×256 | 64 | 4,194,304 |
| 编码器 2 | 128×128 | 128 | 2,097,152 |
| 编码器 3 | 64×64 | 256 | 1,048,576 |
| 编码器 4 | 32×32 | 512 | 524,288 |
| 瓶颈层 | 16×16 | 1024 | 262,144 |

规律：**空间每次减半，通道每次翻倍，总元素数每次减半。** 编码器在做的是「空间上越来越粗，每个位置的信息维度越来越丰富」。解码器再把浓缩的语义铺开成逐像素答案，并用跳连接回高分辨率细节。

## 四、模型的输入与输出

| 维度 | 输入 | 输出 | 变了吗 |
| --- | --- | --- | --- |
| 批量 | B | B | 没变 |
| 通道 | 3（红绿蓝） | 1（是不是细胞核） | **变了** |
| 高 | 256 | 256 | 没变 |
| 宽 | 256 | 256 | 没变 |

**空间尺寸不变是 U-Net 特意设计的目标**，不是所有网络的通性（分类网络输入 `(B,3,32,32)` 输出 `(B,10)`，空间维度直接消失）。分割的答案本身要和原图逐像素对应，所以必须绕一大圈再回来。

**每个输出像素不是由对应位置的单个输入像素决定的**，而是由输入图上以它为中心的一片区域（感受野）共同决定的。判断「这里是不是细胞核」必须看周围的形状和纹理，光看一个像素的灰度毫无意义。

**完整的三步流程**

```
输入 (B,3,256,256)
  → U-Net → logits (B,1,256,256)      ← 模型到此为止，数值可为任意实数
  → sigmoid → 概率 (B,1,256,256)       ← 压到 0~1
  → 阈值 0.5 → 掩膜 (B,1,256,256) 0/1  ← 算指标时做
```

**logits ≠ 概率**。模型原始输出叫 logits（得分），可以是 -3.2、5.1 这种值；sigmoid 之后才是概率。

## 五、可视化技巧

```python
plt.imshow(image)
plt.imshow(np.ma.masked_where(mask_bin == 0, mask_bin), alpha=0.5, cmap="autumn")
```

`imshow` 对数组里每个像素都会给颜色，直接画掩膜会把整片背景也涂上色。
`np.ma.masked_where(条件, 数组)` 是 numpy 的**掩码数组**机制：「凡是满足条件的元素标记为无效，绘图时透明」。

参数顺序是**先条件、后数组**。`mask_bin == 0` 表示把背景遮掉，只给前景上色。

术语撞车提醒：这里的 "mask" 是动词，意思是「遮起来不画」；一直说的「掩膜 / mask」是名词，指标注数据本身。

- `alpha`：透明度，0 全透明、1 不透明
- `cmap`：配色方案，把数值映射成颜色的规则表（`gray` 黑白、`autumn` 黑红黄）
- `vmin` / `vmax`：固定数值到颜色的映射范围，想让前景稳定显示某个颜色就加上

更短的等价写法：`ListedColormap(["none", "red"])`——值 0 透明、值 1 红色。

## 六、附录 A：Python 与代码组织

**`DSBDataset` / `UNet` 这种名字是哪里来的**
自己定义的，不是库里的东西。`class DSBDataset(Dataset)` 就是「造一个继承自 `Dataset` 的新类」。

对照：`class Net(nn.Module)` 里的 `Net` 也是自定义名字，PyTorch 只提供 `nn.Module` 这个基类。

**基类给什么**：`Dataset` 提供索引取值 `dataset[0]`、`len()`、被 DataLoader 识别；要求你实现 `__len__` 和 `__getitem__`。不继承 `Dataset`，DataLoader 会直接报错。

**定义和使用必须能互相找到**：同一个文件里直接写名字就行；跨文件要用 `from data import DSBDataset`，不 import 就用会报 `NameError`。

## 七、附录 B：损失与 Dice 指标

**损失是什么**
给模型这次答题打分。训练就是「算损失 → 求导 → 把参数往损失变小的方向挪 → 重复」。

**BCE（二元交叉熵）**
逐像素比较预测和标签。单个像素：`损失 = -( y·log(p) + (1-y)·log(1-p) )`

| 真实标签 | 预测 | 损失 | 含义 |
| --- | --- | --- | --- |
| 1 | 0.9 | 0.105 | 答对，几乎不罚 |
| 1 | 0.1 | 2.303 | 答错，重罚二十倍 |
| 0 | 0.1 | 0.105 | 答对 |
| 0 | 0.9 | 2.303 | 答错 |

对数的意义：**越自信地答错，罚得越狠**。

**为什么用 `BCEWithLogitsLoss`**
模型输出是 logits（没经过激活），这个名字里的 "WithLogits" 表示内部已含 sigmoid，且数值更稳定。自己先 sigmoid 再算交叉熵会遇到 `log(0)`，结果变成 `inf` 或 `nan`。
**所以模型最后一层不要加 sigmoid**，加了两遍会训不动且不报错。

能手算的验证：logit = 0 → 概率 0.5 → 损失 = ln2 ≈ 0.693；logit = 2.197 → 概率 0.9 → 损失 ≈ 0.105。

**BCE 的短板**
它是对所有像素求平均，前景占比低时，模型全猜背景损失就已经很小，没有动力学前景。这就是需要 Dice 的原因。

**Dice 系数**
`Dice = 2 × 交集 ÷ (区域A面积 + 区域B面积)`，0 到 1，1 是完全重合。

手算例子：真实 1000 个前景像素，预测 900 个，其中 800 个对上 → `2×800 ÷ (900+1000) ≈ 0.842`。
同一组结果的 IoU 是 `800 ÷ 1100 ≈ 0.727`——**同一次结果，Dice 总比 IoU 大**。

**软 vs 硬**（关键区分）

- **损失用软概率**：直接用 0.83 这类连续值算，因为阈值化不可导，梯度传不回去
- **指标用硬 0/1**：阈值 0.5 化之后再算，因为人看的是这个

对应 `net.py` 里的两个函数：`dice_loss`（软，不阈值化）和 `dice_coeff`（硬，阈值化）。

**两种 Dice 算法**：把所有像素混在一起算一个总 Dice，还是每张图各算一次再平均。
`net.py` 用的是后者：`flatten(1)` 后 `sum(dim=1)` 得到每张图一个值，最后 `.mean()`。

**eps = 1e-6 的作用**：防止除零；还有一层约定——如果标签和预测都是全空，Dice 算作 1（两边都空视为预测正确）。

**组合损失**：`combined_loss` = `bce + dice_loss`。BCE 提供稳定的逐像素梯度，Dice 直接优化重叠率。这是 v1（纯 BCE）到 v2 的改动点。
